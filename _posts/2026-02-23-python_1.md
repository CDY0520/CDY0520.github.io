## Runtime Error
파이썬의 난이도는 ‘문법’이 아니라 ‘구조/철학/환경’에서 나온다.  
입문 단계에서는 파이썬이 쉬운 것처럼 느껴질 수 있지만 실무로 갈수록 반드시 이해해야 하는 것이 있다.
<br>
파이썬은 동적 타이핑 언어이다. 타입을 선언할 필요 없이 원하는 값만 넣으면 된다.  
이 덕분에 파이썬은 ‘쉬운 언어’로 보이지만, 이 유연함이 버그의 근본 원인이 된다.  
<br>
타입이 실행 중에 자유롭게 바뀌기 때문에, 에러 위치가 코드 앞부분에 숨어 있게된다.  
또한 조건문이나 연산문에서 예상치 못한 타입끼리 계산되는 버그가 발생하기도 한다.  
<br>
파이썬은 프로그램이 실행되는 런타임에 변수의 타입을 확인한다.  
따라서 코드를 작성하는 시점(컴파일 타임)에는 오류가 없어도, 실제 프로그램을 실행했을 때 예상치 못한 타입 에러가 발생할 수 있다.  
이렇게 런타임에 타입 오류가 발생하므로, 초보자는 에러 메시지를 이해하기 어렵다.  
<br>

![](/assets/img/python_1-1.PNG)

위 코드처럼 add 함수는 숫자도 문자도 각각 처리할 수 있지만,  
숫자와 문자를 함께 넘기면 런타임에 TypeError가 발생하게 된다.  
<br>
코드 규모가 커질수록 이런 오류를 찾기는 더욱 어렵게 될 것이다.  
파이썬은 문법이 쉬운 것이지, 타입 시스템은 결코 단순하지 않다.  
프로젝트가 커질수록 타입힌트(type hints)가 필요해지는 이유가 여기에 있다.

## Type Hinting

![](/assets/img/python_1-2.PNG)

파이썬 3.5부터 도입된 타입 힌팅은 코드 실행에는 영향을 주지 않으면서,  
개발자에게 변수나 함수의 인자 또는 반환 값의 타입을 알려주는 기능이다.  
<br>
이를 통해 코드 가독성을 높이고, 잠재적인 타입 에러를 미리 찾아낼 수 있도록 돕는 역할을 한다.  
또한 코드를 더 견고하고 이해하기 쉽게 만들어 주며, 파이썬의 동적 타이핑 문제를 보완해 준다.  

<hr style="height: 5px; background-color: #777; border: none;">

## 들여쓰기(Indentation)

![](/assets/img/python_1-3.PNG)

파이썬은 들여쓰기로 코드 블록을 구분한다.  
이는 파이썬 코드가 다른 언어에 비해 간결하고 읽기 쉽다는 장점이 되면서  
동시에 초보자들이 가장 많이 실수하고 디버깅에 어려움을 겪는 부분이기도 하다.  
<br>
잘못된 들여쓰기는 단순한 습관 문제가 아니라 문법 에러로 이어지게 된다.  
들여쓰기가 올바르지 않으면 IndentationError 또는 TabError를 발생시키고 코드를 실행하지 않는다.  
이렇게 오류가 발생하더라도 어디가 문제인지 찾기 어렵다. 눈으로 보기엔 멀쩡한데 코드가 이상하게 실행된다.  
<br>
또한 들여쓰기가 잘못되면 조건문이나 반복문 내부 코드가 의도와 다르게 밖으로 빠져나가는 버그가 발생하기도 한다.  
같은 줄에 스페이스 4개의 빈칸 공간과 탭 1개의 공간이 겉으로는 같아 보이지만 실제로는 완전히 다른 코드가 되어버린다.  
복붙 과정에서 들여쓰기 수준이 엉키면 오류 메시지가 엉뚱한 곳을 가리킨다.  
Jupyter Notebook처럼 셀 단위 실행 환경에서는 들여쓰기 오류가 더 늦게 드러난다.  
<br>
들여쓰기가 단순하다는 건 '읽기' 기준이지, '코드를 정확히 제어하는' 기준은 아니다.  
파이썬이 쉬워 보이지만 구조적 사고를 강제하는 언어라는 점 때문에 초보에겐 오히려 어렵다.

## 가상 환경(Virtual Environment)
파이썬 개발을 시작하면 다양한 외부 라이브러리(패키지)를 사용하게 된다.  
그런데 이 패키지들은 각기 다른 버전과 의존성을 가질 수 있다.  
이때 가상 환경을 사용하지 않으면 '패키지 충돌 지옥'에 빠지게 된다.  
<br>
나도 처음 프로젝트 수행할 때, 이 부분에 대해 잘 몰라서 계속 패키지 버전 깔고 지우고 반복했다!  
<br>
예를 들어 여러 파이썬 프로젝트를 진행한다고 가정해보자.  
프로젝트 A: Django 2.0과 requests 2.10을 사용  
프로젝트 B: Django 3.0과 requests 2.20을 사용  
<br>
이 두 프로젝트를 하나의 파이썬 환경에서 개발 할 때, 발생하는 오류가 바로 패키지 충돌이다.  
<br>
Django==2.0 설치 후 Django==3.0을 설치하면, 이전 버전이 덮어씌워져 프로젝트 A가 깨질 수 있다.  
requests 라이브러리도 마찬가지로 한 프로젝트에서 요구하는 버전이 다른 프로젝트와 충돌할 수 있다.  
<br>
결과적으로 한 프로젝트를 위해 패키지를 업데이트하면  
다른 프로젝트가 작동하지 않게 되는 악몽 같은 상황이 반복해서 벌어지게 된다.  
<br>
이때 사용할 수 있는 방법이 바로 가상 환경이다.  
가상 환경은 '프로젝트별 독립 공간'이라고 생각하면 된다.  
<br>
각 가상 환경은 자신만의 파이썬 인터프리터와 피키지 디렉토리를 가지므로,  
패키지 설치 시 다른 프로젝트에 영향을 주지 않기 때문에 유용하다.  
<br>
또한 라이브러리를 지웠다가 다시 설치해도 계속 오류가 날때는  
버전을 살짝 낮춰서 설치하니까 해결되는 경우도 많았으니 참고하도록 하자.

## Note: 실행은 쉽지만, 파이썬의 실행 구조는 결코 간단하지 않다.
내부적으로 파이썬은 인터프리터 언어이며, 이 때문에 실제 동작 과정은 생각보다 복잡하다.  
<br>
인터프리터 언어에서 발생하는 문제들  
1) 실행 속도가 C, Java보다 느린 이유가 명확하게 존재한다.  
2) GIL(Global Interpreter Lock) 때문에 CPU 병렬 작업이 제한된다.  
3) 파일로 실행할 때와 Jupyter Notebook에서 실행할 때 동작이 다르다.  
4) import한 패키지가 캐싱되어, 업데이트해도 바로 반영되지 않는 현상이 발생한다.  
<br>
파이썬에서는 셀을 여러 번 실행하면 변수 상태가 꼬이는 문제가 발생한다.  
멀티프로세싱/스레드 사용 시 속도가 더 느려지며,
온라인 예제 코드와 동일하게 작성했는데 버전 차이로 실행이 안 되는 문제도 빈번하게 발생한다.  
<br>
파이썬이 쉬운 이유는 빠른 실행 환경 때문이지, 언어의 내부 구조가 단순해서가 아니다.  
<br>
실무에서는 GIL, 버전, 환경, 패키지 충돌 같은 영역 때문에 난이도가 훨씬 증가한다.  
따라서 실무로 갈수록 위와 같은 내용들을 반드시 이해해야 한다.

## [SUMMARY]
1. 런타임 에러: 변수의 타입을 확인한다. 동적 타이핑은 편하지만 예측 불가능한 버그를 만든다.  
2. 문법 에러: 들여쓰기(Indentation)에 주의한다. 문법은 단순하지만 실수에 매우 민감하다.  
3. 패키지 충돌 에러: 가상 환경(Virtual Environment)을 활용한다.  
4. 인터프리터 구조와 생태계 특성 때문에 환경 설정 난이도가 높다.
