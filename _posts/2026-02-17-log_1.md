## 개요
- 목표: 항생제 내성 여부 이진분류를 위한 데이터셋 구축  
- 핵심: SQL을 통해 비정형 데이터를 0(미발생)과 1(발생)의 구조화된 피처로 변환  
<br>

>AI는 구현의 속도를 높여주지만, 데이터의 정합성을 보장하고 분석 목적에 맞는 구조를 설계하는 것은 설계자의 도메인 이해도에 달려 있다.

## 텍스트 속에 숨은 내성균과 특정 항생제 내성 여부 찾기: FOR_PREDICT 테이블 설계

![](/assets/img/log_1-1.PNG)

항생제 내성 검사 데이터는 그 가치에 비해 다루기가 매우 까다롭다.  
가장 큰 문제는 원천 데이터가 비정형 텍스트(Unstructured Text) 형태라는 점이다.  
<br>
원천 데이터를 살펴보면 위쪽 사진처럼 컬럼이 구성되어 있다.
<br>
<br>


![](/assets/img/log_1-2.PNG)

거기서 검사결과 컬럼의 데이터 내용을 더 자세히 살펴보면,
위쪽 사진처럼 모델에 바로 사용하기 어려운 텍스트 형태로 되어있다.
<br>
<br>


![](/assets/img/log_1-3.PNG)

다른 팀원이 NLP 모델을 통해 1차 정제를 마쳐 위쪽 사진처럼  
검사결과에서 분석에 필요한 내용을 컬럼으로 쪼개서 PARSED_DATA_FINAL 테이블을 만들었다.
<br>

하지만 여전히 모델 학습에 바로 쓰기에는 어려웠다.  
균주명과 항생제 결과가 파편화되어 있어, 모델이 '어떤 균이 어떤 항생제에 내성을 보이는지' 직관적으로 이해하기 어렵다.
<br>

내가 맡은 역할은 검사결과 컬럼이 자연어 처리를 통해 1차 정제된 PARSED_DATA_FINAL 테이블을 활용하여  
모델이 학습과 통계 대시보드에 활용할 테이블인 FOR_PREDICT 테이블을 설계하는 것이다.  
단순한 데이터 추출이 아니라 이 테이블 설계의 핵심은 의학적 가이드라인을 데이터 구조화 하는 것이다.
<br>

모델이 '내성(1)'과 '비내성(0)'을 구분하려면,  
특정 균주와 특정 항생제가 결합된 명확한 시그널이 필요하다.
<br>

선행 연구 및 관련 가이드라인 자료등을 바탕으로  
'균주 + 항생제 + 결과'를 하나의 논리적 단위로 묶어 0과 1로 변환하여 컬럼화 할 계획이다.

<hr style="height: 5px; background-color: #777; border: none;">

## 도메인 로직을 SQL로 전환하기: 희소 행렬
이 SQL의 핵심은 가장 효율적으로 학습할 수 있는 희소 행렬(Sparse Matrix) 형태의 기반을 만드는 것이다.  
희소 행렬은 행렬의 대부분 요소가 0인 행렬로, 메모리 낭비를 줄이고 계산 효율을 높이기 위해  
0이 아닌 요소(non-zero)의 위치와 값만 저장하도록 한다.  
0이 많이 포함될수록 희소성(Sparsity)이 높다고 하며, 대규모 데이터 처리를 위해 이 방법을 적용하기로 했다.   
<br>

```
-- 1단계: 균주명 그룹화 및 전처리
WITH base_with_abbrs AS (
  SELECT 
    ...,
    -- 복잡한 균주명을 0과 1의 논리적 스위치로 변환
    CASE WHEN org_name LIKE '%Enterococcus%' THEN 1 ELSE 0 END AS EFU,
    CASE WHEN org_name IN ('Escherichia coli', 'Klebsiella pneumoniae'...) THEN 1 ELSE 0 END AS CRE,
    ...
  FROM parsed_data_final
)
```

먼저 수많은 균주명 중 분석 대상인 CRE, EFU 등 핵심 균주를 그룹화하는 작업을 선행했다.  
균주명 약어는 관련 자료들의 사전 조사를 통해 공식적인 용어를 사용했다.  
<br>
<br>

```
-- 2단계: 특정 조건의 내성 발생 여부 플래깅(Flagging)
SELECT 
  ...,
  CASE 
    WHEN CRE = 1 AND LOWER(abx_name) LIKE '%imipenem%' AND intp_code = 'R' 
    THEN 1 ELSE 0 
  END AS "CIMP(R)" -- CRE이면서 Imipenem에 내성(R)이 있는 경우
FROM base_with_abbrs
WHERE intp_code = 'R';
```

내성균 판정은 '균주'와 '항생제' 그리고 '결과'의 조합을 활용한다.  
특정 균주 그룹에서 특정 항생제에 내성이 발생한 상태를 1로 마킹하여, 모델이 집중해야 할 타겟을 명확히 한다.  
이를 SQL 레벨에서 미리 계산하여 모델의 연산 부담을 줄이려고 한다.  
<br>
추가로 병원 데이터 특유의 대소문자 혼용 이슈를 LOWER() 함수와 LIKE 패턴으로 방어한다.  
<br>
<br>

![](/assets/img/log_1-4.PNG)

그렇게 해서 위쪽 사진처럼 최종적으로 FOR_PREDICT 테이블이 설계되었다.

## Note: 설계의 효율이 가져온 비즈니스 임팩트
정교하게 설계된 데이터는 프로젝트 전체의 비용을 줄여준다.   
<br>
Python에서 무거운 문자열 연산을 수행하는 대신,  
DB 엔진에서 정제된 이진 데이터(Binary Data)를 넘겨줌으로써 모델 학습 속도도 신경 썼다.  
<br>
이 테이블은 예측 모델을 넘어, 향후 구축할 통계 대시보드에서 내성 발생률을 집계하는 공통 데이터 마트로서 기능하게 설계했다.  
이는 유지보수 효율성을 극대화하는 전략적 선택이다.
<br>
>비정형 텍스트를 그대로 모델에 학습시키기보다,  
>분석가가 직접 의미 있는 조합(Interaction)을 피처로 만들어 전달하는 것이  
>모델의 설명 가능성(Explainability)과 정확도를 동시에 잡는 지름길일 것이다.  
<br>

사실 비전공자로서 '희소 행렬' 같은 데이터 공학적 용어를 먼저 알고 이 쿼리를 짠 것은 아니였다.  
다만, '모델이 내성 여부를 가장 명확하게 판단하려면 어떤 모양의 표를 원할까?'라는 질문을 스스로에게 계속 던졌다.  
<br>
고민 끝에 균주와 항생제 조합을 0과 1로 치환하는 구조를 설계했고,  
이후 이것이 머신러닝 학습에 최적화된 방식임을 확인했다.  
이론을 먼저 암기하기보다 문제의 본질을 해결하기 위한 구조를 고민하는 과정을 항상 경험하게 되는 것 같다.
